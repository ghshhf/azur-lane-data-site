# 配装引擎与官方档案接入（2026-09-22）

## 一、这个站要解决的三件事

按建立时的初衷拆开：

1. **不会配装** → 引擎直接给出「装什么」，而不是给一堆装备让人自己挑。
2. **不知道配装后战力怎么样** → 装前/装后的面板与战力对比，单看「综合性能 3726」这种黑盒数字不够。
3. **只能用手上已有的装备** → 推荐必须受仓库约束（持有 + 件数），并能反过来说清「差哪几件」。

数据层原本就埋好了输入：`playerOwned` / `count` / `enhanced`（库存）、`fitShipTypes`（适配）、`equipment.actual`（实装）、`fleets.equipmentTips`（历史配装）、`fleetStats.综合性能`（旧的手工战力）。缺的是**「算」的那一半**。

## 二、数据来源分两层

先把口径来源分清，否则无法判断哪个数字可以信：

| 层 | 内容 | 来源 | 可信度 |
|---|---|---|---|
| ① | 舰娘面板、槽位、槽位武器效率 | 官方档案（AzurAPI，`scripts/fetch-official.mjs` 生成） | 游戏内数值，可逐项核对 |
| ② | 三轴权重、归一锚点、分档线、强化系数 | 自建 | 游戏不公布战力公式，只能自定 |

产物两个文件，共 44 KB，只含本站收录的舰娘：

- `src/data/shipSlots.json` —— 槽位构成 + 武器效率三档
- `src/data/shipPanels.json` —— 官方分档面板（1 / 100 / 120 / 125 级，改造船另有改造档）

重新抓取：`npm run fetch:official`（走镜像，原始数据缓存到 `.cache/`，已 gitignore）。

## 三、接入官方档案修正的三处口径错误

此前引擎的三块输入都是错的，且每一块都会让结果整体偏。

### 1. 槽位：本站 `slots` 不是游戏内槽位

`src/data/ships.json` 的 `slots` 是**去重后的槽型列举**，不是槽位表：

| 舰娘 | 本站旧 slots | 官方槽位（武器槽，不含设备槽） | 差异 |
|---|---|---|---|
| 阿拉巴马 | 战列主炮 ×3、防空 ×1（缺副炮、含虚拟设备槽） | 主炮 ×3、副炮 ×3、防空 ×1（7 武器槽） | 副炮线丢失、设备槽为虚拟 |
| 西弗吉尼亚 | 主炮、副炮、防空、设备 ×2 | 主炮 ×3、副炮 ×3、防空 ×1（7 武器槽） | 副炮压成 1、设备槽为虚拟 |
| 亚特兰大 | 轻巡主炮 ×2、防空、鱼雷 | 通用炮 ×1、鱼雷 ×2、防空 ×1 | 主炮/鱼雷数量都错 |
| 拉菲II | 炮击、鱼雷、防空（3 项） | 主炮 ×1、鱼雷 ×2、防空 ×1（4 项） | 鱼雷槽少 1 个 |

官方 `slots[].max` 的语义按舰种不同（已用官方 wiki 装备槽表逐舰核对）：
- **水面舰（BB/CL/CA/DD）**：每类型只列 1 条，`max` = 该类型槽位数。阿拉巴马 `BB Guns max=3` = **3 个主炮槽**，与游戏内实装及用户 LV.125 截图一致。
- **航母（CV/CVL）**：每条 `slots` 元素 = 1 个装备槽，`max` 是载机容量（忽略）。普林斯顿/皇家方舟/信浓/独角兽均如此。
- 例外：舰队航母（如企业 3+3+2=8 槽）仍用 `max` 计槽，但本站舰队不含，航母统一按元素数计槽；新增舰队航母需回 wiki 复核。
`scripts/fetch-official.mjs` 据此两段式生成（水面 `count=max`、航母 `count=元素数`）。

### 2. 设备槽需要补，官方 `slots` 里没有

官方 `slots` 只列武器槽与改造类槽，全库 614 艘里出现 `Auxiliaries` 的只有 12 条特例船。而碧蓝每艘船固定 2 个设备槽（战列装备位＝主炮、副炮、防空、设备×2）。补齐规则写在 `src/utils/slots.js`，依据记在 `slotRules.json` 的 `notes`。

### 3. 面板：把两个方向不一致的手填值当成了基准

原来的基准是 `ships.stats`，它与 `fleetStats.hp` 差到 −62% ~ +166%，方向还不一致。用官方分档面板做裁判（按等级线性插值），对能对照的 11 艘：

| 舰娘 | 等级 | 官方插值 | 本站 stats 偏差 | fleetStats 偏差 |
|---|---|---|---|---|
| 拉菲II | 125 | 2029 | +4% | +14% |
| 独角兽·改 | 125 | 5464 | **−41%** | +6% |
| 巴尔的摩 | 124 | 4676 | −10% | +14% |
| 阿拉巴马 | 107 | 7304 | **+71%** | +1% |
| 圣路易斯 | 103 | 3320 | −16% | +2% |
| 布莱默顿 | 100 | 4382 | −13% | +4% |
| 亚利桑那 | 93 | 6084 | **+81%** | −2% |
| 普林斯顿 | 98 | 4265 | −34% | −1% |
| 亚特兰大 | 64 | 2251 | +7% | −3% |
| 西弗吉尼亚 | 65 | 4800 | **+140%** | −10% |
| 格里德利 | 74 | 1282 | +9% | +7% |
| | | 平均绝对偏差 | **38.8%**（中位 15.7%） | **5.8%**（中位 3.9%） |

结论：`fleetStats` 与等级自洽（中位差 3.9%，差值方向也不随等级单调，见下），`stats` 是按舰种拍的概数——BB 一律填 11000–12500、SS 只有 2200 一个值。

**「是不是等级升级了」这个假设可以排除**：若 `stats` 是升级前的旧面板，它应系统性小于当前值，但 13 艘里有 6 艘反过来（最大 +166%），且差值不随等级单调（相关系数 −0.48、比值跨度 0.55–2.66）。它不是任何等级下的面板。

引擎现在的口径：官方分档面板按等级插值；改造船取改造档。官方未收录的舰娘回退用 `stats`，界面会标注「面板：本站 stats」。

### 4. 顺带修掉的键名冲突

`spd` 在两份数据里含义不同——舰娘的是**航速**、装备的是**机动**。引擎原先把两者相加，生存轴实际在拿航速当承伤因子。现统一为 `eva` = 机动、`spd` = 航速，装备数据里那两件（高性能舵机、重樱的邀请函）已改名。

### 5. 实机截图校验：阿拉巴马 LV.125

用户提供两张实机截图（`clipboard-2026-09-22T04-00-49-881Z` / `886Z`）：面板页与装备页。拿来跟官方 lv125 插值面板和 `shipSlots.json` 对照：

## 四、武器效率

官方 `slots[]` 给三档，614 艘全覆盖：

- `minEfficiency` —— 未突破
- `maxEfficiency` —— 满突破
- `kaiEfficiency` —— 改造后（仅 269 个槽位有）

突破每阶的提升也可核（阿拉巴马主炮：100% → +5% → +10% → +15% → **130%**）。

数据里手抄的那两处刚好印证了口径：西弗吉尼亚备注写「主炮115%/副炮200%/防空100%」，官方是主炮 100→130、副炮 200、防空 100——**副炮与防空两处完全一致，主炮的 115% 正是二破档**（100 +5 +10）。所以引擎取满突破值，与实际持有状态（满破）一致。

设备槽与特殊兵装槽不参与效率缩放。

## 五、引擎结构

| 层 | 文件 | 职责 |
|---|---|---|
| 槽位口径 | `src/utils/slots.js` | 官方槽位展开 + 设备槽补齐 + 可装性判断（纯数据逻辑，运行时与校验脚本共用） |
| 可装性规则 | `src/data/slotRules.json` | 槽位类型 ↔ 装备类型的映射与是否按舰种过滤 |
| 战力模型 | `src/utils/combat.js` | 面板合成 + 三轴归一 + 加权 → 0–1000 评分 |
| 求解器 | `src/utils/fit.js` | 库存约束下的组合搜索 + 缺口清单 + 全舰队盘点 |
| 界面 | `src/pages/Fitting.jsx` | 配装台 `/fitting` |

**求解器为什么是搜索而不是贪心**：评分在两处锚点做了截断，截断之后目标不再可加，逐槽独立取最优不等于全局最优（第一版就是这么写错的，自检抓到 3 处「理论最优低于库存约束最优」）。现在库存解与理论最优走同一套搜索，只放开库存上限。

**槽位变多后补的剪枝**：战列舰从 4 个决策点变成 9 个（3 主炮 + 3 副炮 + 1 防空 + 2 设备），枚举量涨了几个数量级。同型槽（类型、效率、候选集都相同）在语义上可互换，强制候选下标非递减即可剪掉 3! 这类排列重复，配合逐槽 top-5，单舰求解回到可接受范围。

**记录配装按槽位类型落位**：`equipment.recommended` 是按旧槽位顺序写的，槽位表换成官方口径后长度会变。现改为「按哪件装备能装进哪个空槽」依次落位，否则多出来的副炮槽会把后面的装备整体挤错位。

## 六、战力口径 v2

**① 面板合成（纯算术，可逐件回算）**

```
面板 = 舰娘基准（官方插值） + Σ（装备属性 × 槽位武器效率 × (1 + 强化等级 × 0.01)）
```

**② 三轴归一 + 加权**

| 轴 | 公式 | 锚点 |
|---|---|---|
| 输出 | 炮击 + 雷击 + 航空 + 对舰 dps×6 | 2686 |
| 生存 | 耐久 + 机动×10 + 耐久加成×2 + 耐久恢复×10 | 8442 |
| 防空 | 防空 + 防空 dps×10 | 1856 |

锚点取「配满值的 95% 分位」，保证满配时不截断；`npm run test:engine` 每次打印值域诊断，改完口径照着调。

航速（spd）不入任何轴——它不改变承伤，只有机动（eva）进生存轴。

**两个刻意的取舍**

- 分数只用于同一艘船比较不同配装。锚点按单舰面板量级设定，跨舰种横向比没有意义，这点写在界面上。
- 分档衡量配装，不衡量舰娘。分档取「配装效率」＝(本套 − 空装) / (理论最优 − 空装)，分母是同一艘船的跨度，所以驱逐舰配满也能拿 S。

## 七、引擎跑出来的结论

以下数字都不用手工统计，`npm run test:engine` 每次重算：

- **数据记录的配装 9/24 艘超出库存**。阿拉巴马与亚利桑那各记录 3 门 `406mm三连装炮`——3 主炮槽下槽位够装，但库存各只有 1 门；巴尔的摩/布莱默顿/伦敦各记录 2 门 `203mm三连装炮`（实际 1 门）。这正是「记录配装」与「我的仓库」之间的真实落差（属库存缺口，非槽位错误）。
- **全舰队同时配装 10 条装备存在缺口**。最紧的是 `高性能舵机`（需 46 / 有 1）、`四联40mm博福斯`（需 38 / 有 2）、`流星`（需 9 / 有 1）。航母防空炮 `fitShipTypes` 不含 CV/CVL 的问题仍导致 5 艘航母防空槽空着。
- **9 艘存在空槽**。其中 5 艘航母的防空槽是因为防空炮的 `fitShipTypes` 全部不含 `CV`/`CVL`——装备表缺这一档，不是引擎问题。
- **官方档案覆盖 18/24 艘**：槽位与面板都是 18 艘走官方、6 艘回退本站数据（圣哈辛托、特拉法尔加、喀山、拎、鲟·META、黑暗界·META 官方库未收录；拉菲II 与独角兽·改用原型近似，已在数据里标 `match`）。

## 九、闸门

```
npm run fetch:official   重新抓取官方档案（槽位 / 效率 / 面板）
npm run validate         数据校验：主键、必填、引用、槽位规则、官方档案一致性
npm run build            构建（prebuild 自动跑 validate）
npm run test:engine      引擎自检 + 三轴值域诊断（库存记账、可装性、面板插值单调、配装效率边界）
npm run test:smoke       98 个路由渲染断言
npm test                 上面四个连跑
```

官方档案未收录的舰娘不会被拦下——它们走本站回退口径，校验器只提示覆盖率。
