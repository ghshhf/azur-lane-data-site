# 配装引擎设计（2026-09-22）

## 一、这个站真正要解决的三件事

按项目建立时的初衷拆开：

1. **不会配装** → 需要引擎直接给出「装什么」，而不是给一堆装备让人自己挑。
2. **不知道配装后战力怎么样** → 需要装前/装后的面板与战力对比，单看「综合性能 3726」这种黑盒数字不够。
3. **只能用手上已有的装备** → 推荐必须受仓库约束（持有 + 件数），并且要能反过来说清「差哪几件、去哪刷」。

数据层其实已经把输入埋好了：`playerOwned` / `count` / `enhanced`（库存）、`fitShipTypes`（适配）、`slots`（槽位）、`equipment.actual`（实装）、`fleets.equipmentTips`（历史配装）、`fleetStats.综合性能`（旧的手工战力）。
缺的从来不是数据，是**「算」的那一半**——这三件事在界面上一个都没实现。

## 二、三层结构

| 层 | 文件 | 职责 |
|---|---|---|
| 可装性规则 | `src/data/slotRules.json` | 槽位类型（11 种）↔ 装备类型（8 种）的映射与适配开关 |
| 战力模型 | `src/utils/combat.js` | 面板合成 + 三轴归一 + 公开权重 → 0–1000 评分 |
| 求解器 | `src/utils/fit.js` | 库存约束下的组合搜索 + 缺口清单 + 全舰队盘点 |
| 界面 | `src/pages/Fitting.jsx` | 配装台 `/fitting` |

### 为什么需要 slotRules 这一层

数据里槽位类型有 11 种（`战列主炮` / `重巡主炮` / `轻巡主炮` / `副炮` / `炮击` / `鱼雷` / `防空` / `舰载机` / `设备` / `特殊兵装` / `水下装备`），装备类型只有 8 种。两者名字对不上，**没有映射就无法判断一件装备能不能装进某个槽**。两处由实装记录反推的例外写进了规则的 `evidence` 字段：

- `副炮` 槽不按 `fitShipTypes` 过滤 —— 西弗吉尼亚是 BB，副炮槽实装的是 `双联装120mm主炮`（该装备 `fitShipTypes=['DD']`）。
- `设备` 槽接受 `弹药` —— 西弗吉尼亚设备 2 槽实装 `九一式穿甲弹`（type=`弹药`）。反过来，主炮槽**不**接受弹药，否则会占掉一个主炮位。

### 求解器

目标是带约束的组合优化，有确定解：

- **约束**：槽位类型 + 装备适配舰种 + 库存件数（同一件装备的 `count` 是硬上限，同船多槽也扣）
- **搜索**：逐槽取边际分 top-6，再深度优先枚举并做库存记账，节点上限 40 万
- **理论最优**：同一套搜索，只放开库存上限。走同一套搜索是必要的——评分在两轴锚点处做了截断，截断之后目标不再可加，**逐槽独立取最优不等于全局最优**（第一版就是这么写错的，自检抓到 3 处「理论最优低于库存约束最优」）。

## 三、战力口径（自建，不是游戏内数值）

游戏没有公布「战力」公式，官方面板也不直接给战力。所以分两步，第 ① 步零猜测，第 ② 步参数全公开：

**① 面板合成（纯算术，可逐件回算）**

```
面板 = 舰娘基准 + Σ（装备属性 × 槽位武器效率 × (1 + 强化等级 × 0.01)）
```

武器效率只乘在 `fp / trp / aa / air / dps` 上；命中、装填、机动、耐久加成是装备带给舰船的属性，不受效率影响。仅武器槽计入效率。

**② 三轴归一 + 加权**

| 轴 | 公式 | 锚点 |
|---|---|---|
| 输出 | 炮击 + 雷击 + 航空 + 对舰 dps×6 | 1780 |
| 生存 | 耐久 + 机动×2 + 耐久加成×2 + 耐久恢复×10 | 13200 |
| 防空 | 防空 + 防空 dps×10 | 760 |

锚点按已持有 13 艘的实测值域标定（空装 195–480 / 配满 1695 之类），`npm run test:engine` 会打印值域诊断，改完权重照着调即可。

**两个刻意的设计取舍**

- **分数只用于同一艘船比较不同配装**。锚点按单舰面板量级设定，BB 的耐久是 DD 的 6 倍，跨舰种横向比分数没有意义。这一点写在界面上。
- **分档衡量配装，不衡量舰娘**。分档取「配装效率」＝ (本套分数 − 空装分数) / (理论最优分数 − 空装分数)。分母是同一艘船的跨度，所以驱逐舰配满也能拿 S。用绝对分数分档会让驱逐舰怎么配都是 C，那是错的。

## 四、为什么不让模型算配装

配装是带约束的组合优化，有确定解，且每一件都能回算到原始数据。让语言模型直接给配装方案有三个必然问题：库存够不够无从保证、数值无法核验、同一问题两次答案不同。

模型的位置在**解释结果**：为什么推荐这组、换掉某件会怎样、缺口清单翻译成「去哪刷」。算的部分交给求解器。

## 五、引擎首次运行跑出来的结论

这些数字都不是手工统计，`npm run test:engine` 每次都会重算：

- **数据记录的配装 12/24 艘超出库存**。阿拉巴马记录装 3 门 `406mm三连装炮`，实际持有 1 门；亚利桑那同样 3 门；巴尔的摩/布莱默顿/伦敦各记录 2 门 `203mm三连装炮` 而实际 1 门。**这正是「记录配装」和「我的仓库」之间的真实落差**，也是这个引擎最直接的价值。
- **全舰队同时配装，12 条装备存在缺口**。最紧的三条：`40mm博福斯海兹梅耶` 需 12 有 1、`155mm三连装炮` 需 12 有 1、`五联装533mm鱼雷` 需 15 有 8。
- **9 艘舰娘存在空槽（无任何可装装备）**：5 艘航母的防空槽 + 3 艘重巡的鱼雷槽 + 鲟·META 的水下装备槽。
- **14 件持有装备从未出现在任何阵容或推荐里**，属闲置库存。

## 六、数据缺口（需要你定方向）

按「挡不挡路」排序：

1. **槽位武器效率只有 2/24 艘录入**（西弗吉尼亚、特拉法尔加写在 `notes` 自由文本里，没结构化）。效率是武器输出的乘数，缺它整船战力按 100% 算、结果偏低。**这是最挡路的一条**，建议提成 `slotEfficiency` 字段。要么你按游戏内面板报数，要么我按舰种给默认值再逐艘覆盖。
2. **面板口径矛盾**。`ships.stats` 与 `playerInfo.fleetStats.hp` 方向不一致：拉菲II Lv125 是 2111 → 2311（变大），阿拉巴马 Lv107 是 12500 → 7363（变小），西弗吉尼亚 Lv65 是 11500 → 4331（−62%）。这不是等级换算能解释的，看着像两个字段在不同时期手工填、口径不同。**引擎需要一个明确的基准面板口径**，现在用的是 `stats`。
3. **防空炮的 `fitShipTypes` 全部不含 `CV`/`CVL`**，导致 5 艘航母的防空槽在数据里无任何可装装备。
4. **重巡鱼雷槽只有 1 件可用装备**（`四联装533mm鱼雷`）且未持有。
5. **11 艘未持有条目的名称有错**：`ark` 名称是「发」（Ark Royal＝皇家方舟）、`linn` 是「拎」（Lynx＝山猫）、`shinano` 是「十纱」（应为信浓）；`ferry`(KMS Köln) 与「冯矢」、`yujiro`(HMS Eugen) 与「优玖露」中英文互不对应，且 `HMS Eugen` / `KMS Ark Royal` 的国家前缀也是错的。
6. **装备属性是手打糙数据**。官方社区数据（AzurAPI，614 舰娘 / 388 装备）的 `tiers` 里有算期望伤害所需的完整因子——`damage` / `rateOfFire` / `coefficient` / `ammoType` / `range`，本站只有 `dps` 一个标量。但本站 50 件装备对官方数据只匹配上 20 件（译名差异），要对齐得逐件对名。**收益大，成本也实在**。
